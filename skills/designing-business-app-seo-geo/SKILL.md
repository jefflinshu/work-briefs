# Designing Business App SEO/GEO

## Overview

Use mature software-category demand to find users who want to **build, create, customize, or own** their own business system. Brand names create memory; category and query language create acquisition; working templates create conversion.

## Core Principle

Do not start from the product name or from a list of industries. Start from the user's **job-to-be-done**, then separate software-shopping intent from build/custom intent.

**Default taxonomy:** Bookings, Ordering, Dispatch, Registration, CRM, Online Store.

## Workflow

1. **Define ICP and exclusions.** Prefer small businesses, local merchants, and small service operators. Keep enterprise/project-only scenarios separate unless explicitly targeted.
2. **Map each scenario to a Job.** Example: restaurant is an industry; reservations and QR ordering are different Jobs.
3. **Build three query layers:**
   - Mature SaaS: `software`, `system`, `best`, `for small business`
   - Build/custom: `build`, `create`, `make`, `my own`, `custom`
   - AI/no-code: `AI builder`, `without coding`, `no code`
4. **Generate high-intent long tails:** `[build/create] + [industry] + [business system] + [capability] + [AI/without coding]`.
5. **Prioritize templates only after query validation.** Favor mature SaaS categories with clear custom/build demand and an end-to-end workflow that can be demoed.
6. **Separate template count from landing-page count.** Reuse a small number of engines across many genuinely different industry/use-case pages.
7. **Design the page system:** Category → Industry × Job → Template → How-to/Problem → Capability → Comparison.
8. **Measure to activation/revenue.** Do not optimize only for traffic.

## Output Contract

Return, in this order:

1. **Strategic conclusion** — 3–5 sentences.
2. **ICP + scope** — target users and excluded segments.
3. **Job taxonomy** — map scenarios/industries to Jobs and reusable engines.
4. **Query clusters** — mature SaaS, build/custom, AI/no-code, plus capability modifiers.
5. **Template priorities** — P0/P1 with workflow and reusable engine.
6. **Landing-page architecture** — page types, URL examples, and intent served.
7. **SEO + GEO page requirements** — answer-first content, real workflow/demo, boundaries, FAQs, internal links, crawlability.
8. **Measurement plan** — Discover → Intent → Engage → Activate → Revenue.
9. **Next actions** — smallest testable rollout before scaling.

## Guardrails

- Do not assume a catchy brand term is a high-volume query.
- Do not use `template` as the primary demand category when the buyer thinks in terms of an app/system/business outcome.
- Do not create thin pages by swapping only industry keywords.
- Do not treat an industry as one template when it contains multiple Jobs.
- Do not recommend expanding templates before checking query/activation evidence.

## Quick Reference

| Decision | Default |
|---|---|
| Product category | AI App Builder for Small Business / AI Business App Builder |
| Best acquisition intent | Build / Create / Custom / My own / AI / Without coding |
| Site structure | Job first, industry second |
| Template strategy | Few reusable engines, many valuable use cases |
| Primary KPI | High-intent query → template activation / purchase |

## Keyword Intent Generation Reference

When the user gives a target industry, workflow, audience, or product direction, expand search intent in this order.

### 1. Job / system noun

Start with the business outcome users already understand:

- booking / reservation system
- ordering system
- dispatch system
- registration system
- CRM
- online store
- inventory / POS / scheduling when the scenario requires them

Do not start with invented product terminology.

### 2. Mature SaaS intent

Generate category-shopping queries:

- `[system] software`
- `best [system] software`
- `[system] for small business`
- `[industry] [system]`
- `best [industry] [system]`

These validate that an established software category and budget already exist.

### 3. Build / custom intent

Generate ownership/customization queries:

- `build [system]`
- `create [system]`
- `make my own [system]`
- `custom [system]`
- `build [industry] [system]`
- `create my own [industry] app`

These are the highest-priority acquisition intents for an AI business-app builder.

### 4. AI / no-code intent

Generate implementation-alternative queries:

- `AI [system] builder`
- `build [system] with AI`
- `create [system] without coding`
- `no code [system] builder`
- `AI app builder for [industry]`

### 5. Capability modifiers

Add only capabilities that materially alter the workflow, for example:

- WhatsApp
- online payment / PIX
- QR ordering
- calendar
- SMS / OTP
- inventory
- multi-location
- staff roles
- customer portal

Formula:

`[Build/Create] + [Industry] + [Business System] + [Capability] + [AI/Without coding]`

### 6. Intent classification

For each query cluster, label:

- **Software shopping** — user wants an existing SaaS.
- **Build/custom** — user wants ownership or workflow customization.
- **AI/no-code** — user wants a cheaper/faster implementation method.
- **Problem/how-to** — user is researching how to implement a workflow.
- **Capability** — user is searching for a specific integration or operational feature.
- **Comparison** — user is comparing SaaS vs custom/AI alternatives.

Prioritize build/custom and AI/no-code queries only when the underlying SaaS category already demonstrates real demand.

## SEO / GEO Page System

Map intent to pages:

| Page type | Primary intent |
|---|---|
| Category page | broad software/system demand |
| Industry × Job page | verticalized business outcome |
| Template page | working app/system ready to customize |
| How-to / Problem page | implementation question |
| Capability page | integration/feature-specific demand |
| Comparison page | SaaS vs custom / AI / no-code |

Every page should:

1. answer the query directly near the top,
2. identify who the workflow is for,
3. show the end-to-end workflow,
4. show a real runnable/demoable application where possible,
5. state important limits and prerequisites,
6. include useful structured FAQs/data rather than filler,
7. link to the relevant Job, Template, and Capability pages,
8. remain crawlable and indexable.

GEO and SEO should reuse the same factual content assets. Write for retrieval and citation by search engines and AI assistants, not only for keyword density.

## Measurement

Measure the full path:

`Discover → Intent → Engage → Activate → Revenue`

Suggested signals:

- search impressions / indexed queries,
- ranking / click-through,
- AI referral traffic where available,
- template/app opens,
- project creation,
- publish/deploy,
- paid conversion / revenue.

The objective is not maximum traffic. The objective is to discover which high-intent queries reliably lead to a working-template activation and eventually revenue.
